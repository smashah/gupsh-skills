# Connect an owner app to gupsh

This is a condensed implementation checklist from [gupsh-app issue #149](https://github.com/smashah/gupsh-app/issues/149). The canonical owner-app guide is [connect-an-app.md](https://github.com/smashah/gupsh-app/blob/work/wave-0-foundation/docs/guides/connect-an-app.md); the guide currently records that no owner app has been selected and no runtime walkthrough has happened.

1. Create a gupsh site and mint its site UUID and publishable/secret key pair. Use a staging site for staging. Complete sending-domain DNS records shown by the dashboard before email sends.
2. In the app's auth Worker, declare `GUPSH_API_BASE_URL=https://api.gupsh.app/api/v1`, `GUPSH_SITE_UUID`, `GUPSH_PUBLISHABLE_KEY`, and `GUPSH_SECRET_KEY` in `.env.schema`. Inject actual values per environment, register sensitive keys in `worker-env-allowlist.json` and `credentials.manifest.json`, and keep them out of source and client bundles.
3. Create one server-side `Analytics` client with `clientOptions.baseUrl` and the injected keys. In the Better Auth `databaseHooks.user.create.after` path, use the app's `onUserCreated` callback to import a subscriber with `uuid: user.id`, then track `$signed_up`; skip anonymous users. Make gupsh delivery fail open so signup still completes if the API is unavailable.
4. Choose one owner for marketing consent. The current app hook starts its own double opt-in; a gupsh list request must use recorded consent evidence and remain pending until confirmation. A signup checkbox or `$subscribe` event alone does not establish confirmed list membership. Without consent, keep the CRM person ineligible for marketing; use `V1.Commands.unsubscribe` when an explicit global unsubscribe is required. Use `V1.Commands.changeEmail` after a verified email change. On deletion, the server posts to `/api/v1/data_deletion_requests` with Basic auth, site UUID and email; HTTP 200 with `queued_for_anonymization` means queued, not erased.
5. Track a purchase only from a verified payment webhook after storing the order. Set `unique.key` to the provider order ID and `value.amount` to minor units. Track refunds from verified webhook data. Do not send revenue to portfolio analytics.
6. On the website, load `<script src="https://api.gupsh.app/gupsh.js" data-site-uuid="<site_uuid>" async></script>` in a browser-safe path and add forms as needed. Register Expo push devices through the app server after receiving a device token; remove them on logout. Mobile clients never hold the secret key.
7. Verify on staging with a real signup, consent state, purchase, browser event, and push delivery as applicable. Source code and local configuration alone do not prove delivery.
